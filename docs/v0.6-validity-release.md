# ManimBench V0.6 Validity Release

V0.6 is the current engine, suite metadata, and reporting release for cleaner
model rankings. It changes how benchmark evidence is interpreted and published.

## What Changed

- The primary leaderboard score is now a capability score.
- Operational pass/fail is a separate gate with explicit hard checks.
- Required source terms are advisory evidence. They still affect the score, but
  they do not fail an otherwise valid rendered animation by themselves.
- Keyword stuffing remains a hard failure.
- Reports and leaderboard exports now include pass rate, source coverage,
  render success, and failure buckets beside the score.
- Result, manifest, publish, and leaderboard schema versions are now `0.6.0`.

## Why This Matters

Earlier result exports collapsed different evidence into one fail label. That
made debugging hard and made a clean model ranking less trustworthy. Missing
source files, render crashes, visual sanity failures, and exact source-term
misses are not the same model behavior, so V0.6 publishes them separately.

The model ranking should answer: which model produced the best benchmark
animations across the full suite? The diagnostic fields should answer: why did
this run fail or lose points?

## Rerun Requirement

Earlier results are not comparable to V0.6 leaderboard results. Any official V0.6
publish must rerun generation, rendering, scoring, report generation, and
publish from a fresh full-suite run.

Recommended flow:

```bash
manimbench generate-batch --models <models> --provider auto --output-dir outputs --parallel 2 --force
manimbench run-file-matrix --model-output <model>=outputs/<model> --sandbox container --parallel 2 --run-id v06-<date>
manimbench report --run-dir runs/v06-<date>
manimbench publish --run-dir runs/v06-<date> --target draft --site-repo ../manimbench-site
```

Use live publish only after checking the generated report and confirming the
manifest records the official container sandbox and Docker image digest.
