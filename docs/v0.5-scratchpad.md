# ManimBench v0.5 — scratchpad (Codex spec)

Split into **two releases**. Do not implement as one giant change.

| Release | Name | What it delivers |
|---------|------|------------------|
| **First** | **v0.5a — Engine** | OpenRouter generation, v0.5 tasks, export/publish CLI, repo split |
| **Second** | **v0.5b — TUI** | Multi-screen `manimbench` app wrapping the engine |

**Run engine first.** The TUI is a front-end over engine APIs. Building it first means rebuilding it when generate/publish/checkpoint interfaces change. Ship a working CLI pipeline you can spend money on before polishing the dashboard.

## Shared context

### Goal

v0.5 overall:

1. **OpenRouter** for public models with official OpenRouter slugs; **Cursor Agent CLI** for Composer 2.5 while OpenRouter does not publish a Composer slug
2. **Direct per-provider APIs** as optional bypass (OpenAI, Anthropic, Google, xAI)
3. **New public task suite** at `benchmarks/v0.5/`
4. **Repo split** — benchmark on GitHub; site elsewhere
5. **Parallel container rendering**
6. Stable JSON export + publish to manimbench.site
7. **TUI** (v0.5b) — primary daily driver

v0.4 suite stays for historical comparison. v0.5 suite becomes default after v0.5a.

Implementation note: as of v0.5a, OpenRouter's public model catalog does not
include a Cursor Composer 2.5 slug. The engine therefore resolves
`composer-2-5` to the `cursor` provider, which invokes Cursor Agent CLI against
the operator's Cursor subscription. Other public API models continue to use
OpenRouter by default through `--provider auto`.

### GitHub repo scope

**Keep:** runner, tasks, scoring, sandbox, CLI, export/publish tooling  
**Remove:** `website/`, `DESIGN.md`, `PRODUCT.md`, `docs/deploy-site.md`, `build-site`

### Public site (separate repo)

Site is the **oracle** — full results, no obligation to run locally.  
Supports suite versioning (v0.4 vs v0.5). Exclude pro/enterprise tiers.

### Cloudflare publish (production setup)

Current live deploy (from operator dashboard):

| Setting | Value |
|---------|--------|
| Cloudflare project | **manimbench** (Workers & Pages) |
| Git repo | `Ntrpydev/manim-bench` |
| Production branch | `main` |
| Automatic deployments | Enabled |
| Build watch paths | `*` |
| Custom domain | **manimbench.site** |

v0.5a/v0.5b publish should target this pipeline:

- **Site repo** = `Ntrpydev/manim-bench` (HTML/JS + published `data/` + videos)
- **Benchmark repo** = engine only after split (no `website/`); exports JSON + videos for upload
- **Live publish:** commit/push site bundle to `main` on `manim-bench` → Cloudflare auto-deploys to manimbench.site
- **Draft publish:** push to a non-production branch (e.g. `draft`) or use Cloudflare preview deployment URL — not public leaderboard until promoted to `main`

TUI **Settings** screen: GitHub token (push to site repo), optional Cloudflare API token / deploy hook as alternative.  
TUI **Publish** screen: show target branch, commit message, preview URL (draft) vs manimbench.site (live).

Replace stale `docs/deploy-site.md` in engine repo with `docs/publish-to-site.md` describing this flow after repo split.


- `benchmarks/v0.4/` untouched — `--suite benchmarks/v0.4/suite.yaml` still works
- File-backed input: `outputs/<model>/<task_id>.py`
- Container sandbox for official runs

# v0.5a — Engine (implement first)

CLI-first. Operator can fill the leaderboard and publish before TUI exists.

## Recommended order

```
A1 → A2 → A3 → A4 → A5 → A6 → A7 → A8 → A9
```

Each step should be shippable and testable before the next.

---

### A1 — Repo split + cleanup

1. Delete `website/` from this repo.
2. Remove `build-site`, `src/manimbench/site.py`, `tests/test_site.py`, `WEBSITE_ROOT`.
3. Remove `build-site` from `workspaces.py` and `comparison.py`.
4. Keep `manimbench report` → `reports/<run_id>/data/*.json`.
5. Rewrite `README.md` — verify/reproduce focus; link to manimbench.site.
6. Add `docs/reproduce.md`.
7. Remove old benchmark runs and stale artifacts from repo:
   - Clear committed sample outputs / stale leaderboard JSON if any
   - Drop obsolete run IDs from docs
   - v0.5 starts fresh — no v0.4 run data migrated into v0.5 exports

**Done when:** repo is engine-only; pytest passes; report still works.

---

### A2 — Model registry

1. `models/public.yaml` — public leaderboard models; Composer via Cursor Agent CLI until OpenRouter publishes a Composer slug; no pro/enterprise.
2. `models/openrouter.yaml` — model id → OpenRouter slug (verify against openrouter.ai/models).
3. `models/providers.yaml` — optional direct API routing per model.
4. Slim `create-workspaces` — on demand only, not all 27 folders by default.

**Done when:** registry files exist; `manimbench` can load and list public models.

---

### A3 — OpenRouter generation (core)

1. `OpenRouterProvider` in `src/manimbench/providers/openrouter.py` (replace `ApiProviderStub`).
2. Use `build_task_prompt()` — no duplicated prompt logic.
3. CLI:
   - `manimbench generate --model <id> [--task TASK] [--parallel N] [--output-dir DIR]`
   - `manimbench generate-batch --models m1,m2,... [--dry-run]`
4. Response cleanup: strip fences, require `class MainScene`.
5. `usage.json` with real API token/cost when available.

**Done when:** one model generates 6 files via OpenRouter; files render in existing runner.

---

### A4 — Money safety + observability

1. **Don't pay twice:** skip complete model/task outputs unless `--force`. Status: `complete | partial | stale | —`.
2. **Checkpoint / resume:** state in `.manimbench/runs/<run_id>/`; resume without redoing finished work.
3. **Log every API call:** `runs/<run_id>/generation.log` — request id, slug, task, tokens, cost, timestamp.
4. **Smoke:** `--smoke` runs 1 task on 1 model before full suite (CLI; TUI wires this in v0.5b).

**Done when:** batch interrupted mid-run resumes correctly; rerun skips completed tasks.

---

### A5 — v0.5 task suite

1. Create `benchmarks/v0.5/suite.yaml` + `tasks/*.yaml`.
2. Set as default in `paths.py`.
3. Same contract as v0.4: `MainScene`, 60 FPS, 120s, one `.py` per task.
4. Improve v0.4 weak points; stable task IDs once published.
5. Record prompt hash in run manifest.

**Done when:** full suite runs end-to-end on v0.5 tasks via CLI.

---

### A6 — Parallel render + Docker pinning

1. `--parallel N` on `run-file-matrix` (default `1`).
2. Parallelize at task×model render level; cap concurrency (default 2–4).
3. **Pin Docker image by digest** in manifest — not `:latest` alone.
4. Refuse official publish if digest missing.

**Done when:** `--parallel 4` renders multiple tasks; manifest records digest.

---

### A7 — Export, manifest, publish CLI

1. **`leaderboard.schema_version: "0.5.0"`** in export JSON.
2. **Immutable run manifest** — run_id, suite, prompt hash, task hashes, OR slugs, docker digest, git commit, scoring version, publish record.
3. **`manimbench publish --run-dir <id> --target draft|live`**
   - **Draft vs live** on manimbench.site
   - **Atomic publish:** stage all assets → validate → flip pointer; never half-update live
   - Live requires complete run or explicit `--allow-partial` confirm
4. Publish to `Ntrpydev/manim-bench` via git push (see Cloudflare publish section):
   - **Draft:** push site bundle to `draft` branch → preview URL
   - **Live:** push to `main` → Cloudflare auto-deploys manimbench.site
   - Atomic: build full bundle locally → single commit → push (never partial `main`)

**Done when:** CLI generates → renders → reports → publishes draft → publishes live without TUI.

# v0.5b — TUI (implement second)

Wraps v0.5a engine. **`manimbench` with no args launches the TUI.**

Multi-screen app (Textual `Screen` stack). **No wizard/onboarding flow** — screens are for focused tasks, not step-by-step gates. User can always return to Dashboard.

## Screen map

| Screen | Purpose | Enter | Exit | Mock |
|--------|---------|-------|------|------|
| **Dashboard** | Home. Model picker, wallet, selection, Run/Smoke. | App launch, `h` / Esc from elsewhere | — | `manimbench-tui-mockup.png` |
| **Run monitor** | Active or completed batch. Full log, per-model status table, Cancel/Retry. | Auto on Run/Smoke; `o` to reopen last run | `h` / Esc → Dashboard | `manimbench-tui-run-monitor.png` |
| **Model detail** | One model: per-task scores, pass/fail, token cost, paths. | Enter on model in list or Run monitor | Esc → back | `manimbench-tui-model-detail.png` |
| **Video preview** | Play/review rendered MP4 + thumbnail for a model/task. | `p` from Dashboard or Model detail | Esc → back | `manimbench-tui-video-preview.png` |
| **Publish** | Draft vs live confirm. Manifest summary, spend, completeness check. | Publish draft/live from Dashboard or Run monitor | Confirm or Esc | `manimbench-tui-publish.png` |
| **Settings** | API keys, Cloudflare creds, Docker image, default parallelism, spend warnings. | `s` from anywhere | Save or Esc → Dashboard | `manimbench-tui-settings.png` |
| **Run history** | List past runs; open in Run monitor. | `r` from Dashboard | Esc → Dashboard | `manimbench-tui-run-history.png` |

Keep Dashboard uncluttered — detailed log and task breakdown live on Run monitor / Model detail, not crammed into home.

## Recommended order

```
B1 → B2 → B3 → B4 → B5 → B6 → B7 → B8 → B9
```

---

### B1 — Orchestrator interface

Extract/coalesce from A7 into a stable API `src/manimbench/orchestrator.py`:

- `fetch_openrouter_catalog()`, `fetch_balance()`
- `estimate_cost(selected_models)`
- `get_output_status(model, suite)` → complete/partial/stale
- `run_smoke(models)`, `run_batch(models, resume=True)`, `cancel()`, `retry_failed()`
- `publish(run_id, target=draft|live)`

TUI calls orchestrator only — no business logic duplicated in TUI layer.

**Done when:** orchestrator unit-tested; TUI can import it without calling CLI subprocesses.

---

### B2 — App shell + screens

Textual app with screen stack. Build screens in this order:

1. **Dashboard** — match `docs/manimbench-tui-mockup.png` (home):
   - Top strip: balance | est. cost | spent
   - Filters + scrollable model list with checkboxes
   - Compact selection summary + `[ Smoke ]` `[ Run ]` `[ Settings ]` `[ History ]`
   - Mini progress strip when run active (tap `o` for full Run monitor)
   - Footer shortcuts
2. **Run monitor** — full-height log + model status table
3. **Settings** — form for keys and defaults:
   - OpenRouter API key
   - GitHub token + `Ntrpydev/manim-bench` repo + draft/live branches (see Cloudflare publish section)
   - Optional Cloudflare deploy hook
   - Docker image, parallelism, skip-complete, spend warning
4. **Publish** — confirm screen (not a tiny modal)
5. **Model detail** — per-task breakdown
6. **Video preview** — path + open player / inline if feasible
7. **Run history** — past run ids, dates, model counts, pass rate

Static/mock data first; navigation between screens works.

**Done when:** `manimbench` launches to Dashboard; can reach every screen with keyboard.

---

### B3 — Wallet + live $ on selection

Wire orchestrator:

- Live OpenRouter balance in top strip (auto-refresh)
- **Est. cost updates instantly** as models checked/unchecked
- Spent-this-run updates during batch

**Done when:** checking models changes dollar estimate in real time.

---

### B4 — Model list + don't pay twice

- Load full OpenRouter catalog with metadata filters
- Checkboxes for multi-select
- **Output status column:** `complete | partial | stale | —` per model for current suite
- Skip-complete models by default on Run; toggle to force re-run

**Done when:** list reflects real catalog and existing output state.

---

### B5 — Run controls

Wire Dashboard + Run monitor to orchestrator:

- **Dashboard:** `[ Smoke ]` `[ Run ]` — starts batch, auto-pushes **Run monitor**
- **Run monitor:** `[ Cancel ]` `[ Retry failed ]` `[ Publish draft ]` `[ Publish live ]`
- Run respects skip-complete; progress + pass/fail on Run monitor

**Done when:** full generate → render → report cycle works; Run monitor shows live updates.

---

### B6 — Status + logs

- **Dashboard:** output status column (`complete | partial | stale | —`); compact run indicator
- **Run monitor:** per-model `ready | generating | rendering | pass | fail | skipped` + full scrollable log
- **Model detail:** per-task status, score, cost, link to Video preview

**Done when:** status and logs update live on Run monitor during batch.

---

### B7 — Persist + resume

- **Checkpoint / resume:** reopening `manimbench` restores in-progress batch
- **Persist dashboard:** filters, selection, last run id → `~/.config/manimbench/dashboard.json`

**Done when:** kill TUI mid-run, reopen, resume without redoing finished models.

---

### B8 — Publish screen

Dedicated **Publish** screen (not inline confirm only):

- Choose draft vs live
- Show manifest summary: run id, suite, model count, complete/partial, est./actual spend, docker digest
- Live disabled until run complete unless explicit partial override
- Draft → optional navigate to live from Run monitor after review
- Calls orchestrator `publish()`

**Done when:** draft → live publish works with full review on Publish screen.

---

### B9 — Polish + tests

- **Video preview screen** — `p` from Dashboard or Model detail
- **Run history screen** — browse and reopen past runs
- **Notifications** — libnotify when batch finishes (even if on another screen)
- **Settings screen** — full form, not modal
- `cli.py`: no args → TUI (Dashboard); subcommands unchanged for scripting
- Tests: mock orchestrator; smoke launch + screen navigation (skip in CI if headless)
